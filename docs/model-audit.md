# 분기별 모델 감사 (Quarterly Model Audit)

이 사이트는 AI 도구와 모델을 현재형으로 소개합니다. 그 말은 **랩이 움직이면 우리 글이 자동으로 틀려진다**는 뜻입니다. 이 문서는 그걸 주기적으로 잡아내는 절차입니다.

2026-09 감사에서 39개 블로그 글 중 **30개**가 낡아 있었고, 벤더 넷 중 셋이 우리가 모르는 사이에 세대를 넘겼습니다. 아래 규칙은 대부분 그때 **실제로 틀렸던 것**에서 나왔습니다.

## 주기와 트리거

- **정기**: 분기 1회 (1월 / 4월 / 7월 / 10월 첫째 주)
- **수시**: 주요 랩이 플래그십을 발표했다는 걸 알게 됐을 때. 분기를 기다리지 마세요.

## 절차

### 1단계 — 재료 추출 (기계)

```bash
npm run audit:models
```

네트워크·DB 없이 돌아갑니다. 툴 URL 상태와 미러/DB 대조까지 보려면:

```bash
npm run build && node -r dotenv/config scripts/model-audit.mjs --network
```

`--network` 는 사이트맵 대조를 위해 빌드 결과물(`.next/server/app/sitemap.xml.body`)을 씁니다.

스크립트는 **판단하지 않습니다.** 검증할 목록만 뽑아줍니다.

### 2단계 — 1차 출처와 대조 (사람/에이전트)

스크립트가 뽑은 모델명을 아래 페이지의 **현재 라인업**과 비교합니다.

| 벤더 | 확인할 곳 | 주의 |
|---|---|---|
| Anthropic | `platform.claude.com/docs/en/models/overview` | 표에 가격·컨텍스트·지연시간이 다 있음. 하단 **"Legacy models (still available)"** 목록을 꼭 보세요 |
| OpenAI | `openai.com/index/<모델>/` | **발표 페이지 상단 배너가 최신 모델을 가리킵니다.** GPT-6 를 이걸로 찾았습니다 |
| Google (모델) | `ai.google.dev/gemini-api/docs/models` | 현행 목록. Pro / Flash / Flash-Lite 를 구분해서 보세요 |
| Google (폐기) | `ai.google.dev/gemini-api/docs/deprecations` | 모델 목록에 없다고 폐기된 건 아닙니다. 폐기는 여기서만 확인 |
| xAI | `x.ai/news` | 최신 발표가 목록 맨 위 |
| Claude Code 기능 | `code.claude.com/docs/en/agent-teams` 등 | **모델 기능과 harness 기능을 혼동하지 마세요** (아래 참조) |

**벤더 마케팅 페이지는 벤더 문서보다 늦습니다.** 2026-09 시점에 실제로 겪은 사례:

- `codeassist.google` 홈이 "individuals at no cost, no credit card needed" 를 광고하는 동안, 같은 회사 폐기 문서는 그 개인 티어가 **2026-06-18 에 종료**됐다고 명시하고 있었습니다.
- OpenAI 의 모델 릴리스 노트 페이지에 GPT-6 가 없었지만, GPT-5.6 발표 페이지 상단은 GPT-6 를 "최신 모델" 로 링크하고 있었습니다.

**규칙: 폐기·종료·가격은 문서가 이깁니다. 마케팅 홈페이지는 보조 자료입니다.**

### 3단계 — 분류 (여기가 진짜 작업)

> **개수를 세지 말고 문맥을 읽으세요.**
>
> 2026-09 감사에서 이 실수를 **두 번** 했습니다. 처음엔 "낡은 버전 핀 48건" 이라고 보고했는데 대부분 `"Opus 4.8 (previous gen)"` 처럼 **이전 세대를 이전 세대라고 부르는 정확한 서술**이었습니다. 두 번째는 `Gemini 3.5 Pro` 13건을 보고 "출시된 적 없는 모델을 서술한다"고 판단했는데, 읽어보니 그 글은 표에 **"Not shipped / Delayed"** 라고 쓰고 본문에 *"anyone telling you Gemini 3.5 Pro is generally available right now is working from stale information"* 라고 명시하고 있었습니다. 코퍼스에서 가장 잘 쓰인 부분이었습니다.
>
> grep 개수는 **어디를 먼저 읽을지 정하는 용도**일 뿐입니다.

각 언급을 넷 중 하나로 분류합니다.

| 분류 | 예 | 처리 |
|---|---|---|
| **(a) 과거 시점 서술** | "2025년 11월 출시된 Gemini 3 Pro", "Opus 4.8 (previous gen)", "당시 Sol 은…" | **유지.** 정확한 서술입니다 |
| **(b) 현재형 추천·주장** | "지금은 X 를 쓰세요", "X 가 최고다", "X 가 플래그십이다" | **수정.** 감사의 본체 |
| **(c) 제목·FAQ 질문·excerpt·소스 주석·이를 미러하는 앵커텍스트** | 글 제목의 모델명과 그 제목을 인용한 다른 글의 앵커 | **한 묶음으로 동시에.** 한쪽만 바꾸면 질문과 답변이, 앵커와 도착지 H1 이 어긋납니다 |
| **(d) 검증 안 된 능력 주장에 모델명이 붙은 것** | "Anthropic's newer models, **including X**, have closed the spatial-reasoning gap" | **모델명을 떼세요.** 이름만 바꾸면 검증 안 된 주장을 다른 모델에 옮기는 셈입니다 |

### 4단계 — 수정

- 여러 에이전트에 나눠 맡긴다면 **파일 단위로** 나누세요. 같은 파일을 동시에 편집하면 충돌합니다. 블로그는 `lib/blog-data-1~4.ts` 로 갈라집니다.
- 글의 논지를 다시 쓰지 마세요. **현재형 문장만** 고칩니다.
- 제목에 모델명이 박힌 비교글은 **그 시점의 비교가 글의 존재 이유**입니다. 날짜 프레임을 명시하고 회고로 두되, "지금 이걸 쓰라"는 문장만 고치세요.
- **슬러그는 동결.** 제목은 바꿔도 슬러그는 SEO 자산입니다. 슬러그를 바꾸면 301 + 인바운드 링크 정리까지 따라옵니다.

### 5단계 — 검증과 배포

```bash
npx tsc --noEmit -p tsconfig.json
npm run build
npx vitest run
npm run audit:models          # 재실행해서 잡히는 게 줄었는지
```

배포 후 **내용 기준으로** 확인하세요. 상태 코드 폴링은 이 사이트에서 오탐을 냅니다 (`docs` 외 별도 메모 참조).

## 하지 말 것

이 목록은 전부 실제로 막았거나 막았어야 했던 것들입니다.

**1. 공지된 인하율로 새 가격을 계산하지 마세요.**
OpenAI 가 "Luna 80% 인하" 를 공지했어도 `$1/$6 × 0.2` 를 써넣으면 그건 아무도 발표하지 않은 숫자입니다. 절대값을 확인하지 못했으면 **인하 사실만 적고 벤더 페이지를 가리키세요.**

**2. 확인하지 않은 벤치마크·성능·순위 주장을 만들지 마세요.**
벤더가 발표한 수치라도 *어떤 지수에서, 무엇과 비교한 것인지* 까지 확인해야 합니다. 2026-09 감사에서 8개 글이 "GPT-5.6 Sol 이 **GPT-5.5 대비** 토큰 효율 54% 개선" 이라고 썼는데, OpenAI 자체 발표 페이지에는 **54% 라는 숫자 자체가 없었고**, 실제 출처의 비교 대상은 자사 이전 모델이 아니라 **서드파티 지수상 차순위 경쟁 모델** 이었습니다. 숫자는 진짜였고 비교 대상이 틀렸습니다.

**3. 넣을 수 있는 숫자를 다 넣지 마세요.**
검증된 벤치마크가 있어도, **글의 논지가 그 숫자를 필요로 하지 않으면 넣지 마세요.** 추가하는 모든 수치는 다음 분기에 누군가 다시 검증해야 할 부채입니다.

**4. 서드파티가 "무엇을 제공하는지" 를 추측하지 마세요.**
"Cursor 가 Grok 4.5 를 일급으로 제공한다" 를 4.6 으로 올리는 건 **Cursor 에 대한 새 주장** 입니다. 확인 못 했으면 검증된 과거 사건(예: "3.11 릴리스에서 추가됐다")으로 범위를 좁히거나, 모델 나열 표를 버전 중립으로 만드세요.

**5. 모델 기능과 harness 기능을 섞지 마세요.**
2026-09 감사에서 코퍼스가 "Agent Teams" 를 **모델의 능력**이자 **Opus 4.8 이 도입한 것**으로 서술했는데, 둘 다 틀렸습니다. Agent Teams 는 **Claude Code 의 실험 기능**(기본 비활성)이고, 팀원을 어떤 모델로 돌릴지는 사용자가 고릅니다. Opus 4.8 발표가 소개한 건 별개 기능인 Dynamic Workflows 였습니다. **"모델이 X 를 갖는다/물려받는다" 라고 쓰기 전에 X 가 어디에 사는 기능인지 확인하세요.**

**6. 목록에 없다고 폐기됐다고 쓰지 마세요.**
Gemini 3 Pro 는 Google 의 현행 모델 목록에 없지만 폐기 문서에도 없습니다. 쓸 수 있는 건 *"현행 API 모델 목록에 더 이상 나오지 않는다"* 까지입니다. 앱이나 Vertex 에서 계속 제공될 수 있습니다.

## lastmod 규칙

`updated` 는 `lib/blog-types.ts` 에서 **"Last substantive content refresh"** 로 정의되고 `app/sitemap.ts` 가 블로그 lastmod 로 씁니다.

- 본문이 실제로 바뀐 글만 올립니다.
- **readTime 만 바뀐 글, 본문 링크의 앵커텍스트만 바뀐 글은 올리지 마세요.** 기사가 갱신되지 않았는데 갱신됐다고 말하면 그 신호의 값이 떨어집니다.
- `date`(최초 발행)는 **절대** 건드리지 않습니다.
- 툴 페이지는 별도입니다 — `lib/tool-content-revised.ts` 의 `TOOL_CONTENT_REVISED_BY_SLUG` 에 항목을 넣지 않으면 툴 페이지를 고쳐도 사이트맵이 침묵합니다.

## 감사 범위에 함께 넣을 것

모델 외에도 같은 주기로 확인할 가치가 있는 것들입니다. 스크립트가 재료를 뽑아줍니다.

- **툴 `websiteUrl` 리디렉트** — 호스트가 바뀌었으면 인수·리브랜딩 신호입니다. 단, curl 403/000 은 봇 차단인 경우가 많으니 **브라우저로 확인** 후 판단하세요.
- **툴 `pricing` 필드** — 2026-09 감사에서 3건이 틀렸습니다. 벤더 가격 페이지에 무료 티어가 실제로 있는지 보세요.
- **미러/DB 대조** — `lib/tools.ts` 는 DB 폴백입니다. 갈라지면 장애 시 다른 내용이 나갑니다. **알려진 낡은 문자열을 grep 하는 방식으로는 놓칩니다**(실제로 세 건 놓쳤습니다). 필드 단위로 대조하세요.
- **200 을 반환하는 죽은 제품** — 리디렉트 검사로는 절대 안 잡힙니다. Supermaven 은 사이트가 멀쩡히 200 이었지만 벤더 블로그에 "Sunsetting Supermaven" 이 올라와 있었습니다. **의심되면 벤더 블로그·변경 로그를 보세요.**
